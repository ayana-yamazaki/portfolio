# Portfolio Concept

## 「作品集」ではなく、“私はどうプロダクトを作る人か”を伝える

従来のように、

> プロジェクト一覧
> → UI
> → 成果

ではなく、

> **How I Build**
> → 自分の仕事の進め方
> → 各プロジェクトをその証拠として見せる

という構成にする。

中核はこの3つ。

1. **Understand Reality**
   現場やユーザーの現実を理解する

2. **Decide What to Build**
   調査や事業課題から、何を作るべきか決める

3. **Build with AI**
   AI・デザイン・コードを横断して、素早く形にする

この3つは、プロダクトを作る一連の流れでもある。

> **Understand → Decide → Build**
> 現場を理解し、作るべきものを決め、素早く形にする。

ただし、形にすることをゴールにはしない。
リリースではなく、現場で使われ、成果が生まれるところまでをデザインする。
導入・定着は独立したテーマにせず、すべての事例に共通する完成条件として示す。

一言でいうと、

> **UI/UXデザイナーのポートフォリオではなく、Product Builderとしての思考と実行力を見せるポートフォリオ**
